AI 코딩 에이전트, 토큰 요금표만
보면 놓치는 것들

핵심 메시지 AI에게 일을 맡길 때 정말 따져야 할 건 토큰을 얼마나 줄였는가가 아니라, 정해둔 품질 기준을 통과하는 결과물을 얼마나 더 싸고 빠르게 받아내는가이다.
01청구서는 왜 이렇게 나오나 — 요금을 가르는 4개 항목

AI 사용료는 토큰(모델이 읽고 쓰는 텍스트의 단위) 수를 기준으로 매겨진다. 다만 토큰이라고 다 같은 값은 아니다. 성격이 다른 네 가지가 섞여 있고, 단가도 크게 다르다. 이 네 가지만 구분해도 아래 내용이 훨씬 쉽게 읽힌다.

항목 무엇인가 단가 감각 (100만 토큰당)
입력 토큰input 이번 요청에 새로 담아 보내는 텍스트 — 질문, 지시문, 함께 붙인 자료. $5 · 보통
출력 토큰output 모델이 이번에 새로 만들어 돌려주는 텍스트 — 설명, 코드, 결과물 전체. $25 · 가장 비쌈
(입력의 5배)
캐시 쓰기cache write 지금까지 나눈 대화를 "임시 저장소"에 새로 올려두는 작업. 대화 앞부분이 바뀌면 이 저장 작업이 다시 일어난다. $6.25 · 비쌈
(캐시 읽기의 12.5배)
캐시 읽기cache read 저장소에 올려둔 이전 대화를 할인된 값으로 다시 불러와 참고하는 것. $0.5 · 가장 쌈
(입력의 1/10)
💡 구조상 꼭 짚어야 할 부분 — 모델은 새 질문마다 쌓인 대화 전부를 처음부터 다시 훑는다(대부분 캐시 읽기). 단가는 제일 낮지만 대화가 길수록 다시 읽는 양이 불어나 결국 총 청구액을 좌우한다. 실패해서 재시도하면 이 비용이 실패 횟수만큼 겹쳐서 청구된다.
02실제로 벌어지는 일

새 질문을 던질 때마다 AI는 그동안 쌓인 대화를 처음부터 다시 읽는다. 그래서 청구서의 대부분은 이 "다시 읽기" 값에서 나온다. 같은 도구를 쓰더라도 잔무까지 전부 상위 모델에 맡기는 쪽은 요금이 눈에 띄게 더 나오고, 자료 조사나 정리는 하위 모델로 돌리는 쪽은 같은 일을 하고도 훨씬 적게 낸다.

대화를 정리하지 않고 하루 종일 이어가면 그 대화 몇 개가 다시 읽기 요금의 대부분을 만들어내고, 반대로 업무 단위로 끊어 쓰면 같은 양을 처리해도 요금은 확 줄어든다. 지시를 구체적으로 미리 적어두면 재시도가 줄고, 그만큼 전체 토큰도 함께 줄어든다. 여러 AI를 동시에 굴리면 비용이 크게 뛰지만, 필요한 일만 나눠 맡기면 오히려 더 아낄 수 있다.

03성적표를 다시 써야 한다 — 봐야 할 네 가지

① 통과율

사람이 검토했을 때 손대지 않고 그대로 받아들인 비율. 높을수록 AI가 헛손질을 덜 했다는 뜻.

② 통과 1건당 비용

실패·재시도 몫까지 더한 총비용 ÷ 통과 건수. 실제 성적표는 이 숫자다.

③ 검토에 걸리는 시간

AI 비용이 아무리 낮아도 검토가 오래 걸리면 결국 손해다.

④ 다시 시킨 횟수

재시도 한 번마다 다시 읽는 비용이 통째로 붙는다. 비용이 새는 가장 큰 틈.

따지지 말아야 할 질문 — "이번 달 토큰을 몇 % 줄였나?" · 토큰이 20% 줄어도 통과율이 떨어지고 검토 시간이 늘면 오히려 손해
따져야 할 질문 — "기준을 통과한 결과물을 더 싸고 빠르게 받았는가?" (예: 통과율 50%→80% · 1건당 $4.00→$3.00 · 검토 30분→15분 · 재시도 3회→1회 — 총 토큰이 늘어도 이건 성공)

04그래서 뭘 바꾸면 되나 — 네 단계로 나눠보면

1단계 · 맡기기 전 — 준비가 절반이다

◾ 한 번에 다 시키지 않는다 — 통째로 말고 쪼갠 단위로. 실패해도 다시 시키는 비용이 작다.

◾ "끝났다"의 기준을 먼저 적어둔다 — 무엇이면 완성인지 처음부터 명시하면 재시도가 사라져 총비용↓.

◾ 큰 작업은 계획부터 보자고 한다 — 계획 → 승인 → 실행(plan mode). 완성 후 수정은 전체 재청구, 계획 단계 교정은 몇 줄로 끝난다. 지침만으로 작업 시간 약 29%↓.

2단계 · 진행하는 중 — 쌓여가는 대화를 방치 않기

◾ 주제가 바뀌면 새 대화를 연다 — 한 창에서 잇지 않는다(/clear). 청구액의 약 96%가 다시 읽기 — 효과가 가장 큰 습관.

◾ 길어지는 작업은 중간에 요약한다 — /compact로 압축하면 이후 다시 읽기가 요약본 크기로. 외부 압축 도구는 오히려 비싼 저장 비용을 유발할 수 있어 내장 기능이 안전하다.

◾ 같은 방식으로 두세 번 실패하면 멈춘다 — 더 쪼개거나 지시를 바꾸거나 사람이 끼어든다. 재시도 한 번 = 대화 전체 다시 읽기 + 새 출력 청구.

3단계 · 맡길 대상 고르기 — 잔무까지 상위 모델 금지

◾ 판단은 상위 모델, 잔무는 하위 모델 — 설계·최종 확인만 상위 모델, 조사·요약·정리는 하위 모델(/model). 같은 품질에서 비용 54~72%↓.

◾ 통째로 넘기지 말고 나눠서 넘긴다 — 전체를 맡기면 재작업 비용이 아낀 금액을 삼킨다(최대 7배). 버려도 되는 작은 조각만 하위 모델에, 계획·점검은 상위 모델/사람이. 차이는 모델이 아니라 맡긴 범위다.

4단계 · 팀 단위로는 — 한 번 정리해두면 계속 아낀다

◾ 안내 문서는 짧게, 자주 손대지 않는다 — 자동으로 불려오는 규칙 파일(CLAUDE.md 등)엔 꼭 필요한 내용만. 자주 바뀌면 비싼 저장 비용 재발생. 실행 시간 28.6%↓, 출력 16.6%↓.

◾ 되풀이되는 절차는 재사용 문서(Skill)로 묶는다 — 언제·어떤 순서·확인 방법만 짧게. 매번 길게 설명할 필요가 없고 재시도도 준다.

◾ 성과는 네 가지 기준으로, 여러 번 재서 판단 — 실행마다 편차가 커서 한 번 재고 결론 내리지 않는다.

05결국 크기에 맞춰 다르게 쓰면 된다
일의 크기 예시 추천 방법
작은 일 오타 수정, 문구 변경, 항목 하나 추가 AI 하나에 짧고 명확한 지시. 계획·분업 같은 절차는 오히려 낭비.
중간 일 기능 하나 추가, 특정 화면 수정, 자료 정리 짧은 프로젝트 안내문 + 관련 Skill 활용. 자료 위치와 완료 기준을 지정.
큰 일 새 화면 전체, 구조 변경, 복잡한 오류 추적 계획 승인 → 작게 쪼개기 → 잔무는 하위 모델 → 검토는 상위 모델/사람 → 길면 중간 요약
06특히 자주 걸리는 함정 세 가지
  • ① 대화를 정리하지 않고 계속 쓴다 — 서로 다른 업무를 한 창에서 이어가면 쌓인 대화 전체가 매번 다시 청구된다. → 주제가 바뀌면 /clear.
  • ② 잔무까지 최상위 모델에 맡긴다 — 조사·정리 같은 단순 작업까지 제일 비싼 모델에게 시키면 같은 결과에 5~10배를 더 낸 셈. → 잔무는 하위 모델(/model)로.
  • ③ 완료 기준 없이 통째로 던지고 재시도만 반복한다 — "다시 해줘"만 되풀이하면 매번 대화 전체를 다시 읽는 값이 붙는다. → 작게 쪼개고, 끝의 기준부터 정한다.
결국 잘 쓰는 사람은
토큰을 아끼는 사람이 아니라, 정해둔 기준을 통과한 결과물을 더 싸고 빠르게 받아내는 사람이 AI를 제대로 쓰는 사람이다.
